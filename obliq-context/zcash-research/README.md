# Zcash Colosseum Startup Research Context

Research snapshot: 2026-10-04.

Purpose: provide a reusable context pack for designing and building a
serious startup for the Zcash track of the Colosseum Crypto World's Fair.

## Core product rule

Do not start with "what Zcash feature can we demo?" Start with a
valuable financial workflow where public-by-default transaction data
creates a real problem, then use Zcash privacy, selective disclosure,
encrypted memos, payment requests, and wallet infrastructure as product
primitives.

The product should be broader than a hackathon demo. V1 should prove the
core loop, while the architecture and business model should support a
real company.

## Current research conclusion

Zcash already has increasingly capable wallet and infrastructure layers.
The more interesting startup territory is above the wallet layer:
private financial operations, B2B workflows, treasury, payouts,
reconciliation, programmable/selective disclosure, and applications that
make shielded ZEC useful without requiring users to understand Zcash
internals.

Do not default to building another generic wallet, block explorer,
donation page, basic checkout, or simple "send ZEC" interface.
